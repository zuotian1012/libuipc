# Follow-up diagnostics: refresh oracle and TOI values

**Status:** offline labels from complete baseline runs. No collision detection was skipped and no physical trajectory was altered.

## Whole-call refresh oracle

The four-layer cloth stack used a 16x16 quad grid per sheet: 289 vertices and 512 triangles per sheet, or 1,156 cloth vertices and 2,048 triangles total. It ran for 40 frames in three fresh processes. Each run logged canonical active simplex pairs after every DCD pass. Nested synchronized timers measured the detection and filtering core separately from the host-side pair-set analysis. A DCD pass is labeled `zero-new` only when its resulting active set contains no pair absent from the preceding DCD pass.

| Repeat | DCD calls | Calls with nonempty active set | Zero-new calls | Zero-new core time | Diagnostic pipeline time | Optimistic time removal |
|---:|---:|---:|---:|---:|---:|---:|
| 1 | 70 | 42 | 28 | 44.35 ms | 1199.05 ms | 3.70% |
| 2 | 68 | 40 | 28 | 44.35 ms | 1165.23 ms | 3.81% |
| 3 | 70 | 42 | 28 | 41.24 ms | 1184.82 ms | 3.48% |

In these initial three runs, every zero-new call occurred while the active simplex set was empty. Removing all classified zero-new core time at zero cost would yield only 1.036–1.040x speedup on these synchronized diagnostic runs, below the plan's 1.2x gate. This is an optimistic arithmetic bound, not a measured speedup or a deployable skip rule. The first call has no preceding set and is left unclassified.

### Replication on 2026-09-17

After adding a stronger vertical-slab separation check and writing frame records to independent files, three more full-baseline runs reproduced the same qualitative speedup bound. They also found one exception to the initial all-active-calls-have-new-pairs observation:

| Repeat | DCD calls | Calls with nonempty active set | Zero-new active calls | All zero-new core time / pipeline |
|---:|---:|---:|---:|---:|
| 4 | 70 | 42 | 0 | 45.38 / 1220.11 ms = 3.72% |
| 5 | 68 | 40 | 0 | 39.77 / 1192.61 ms = 3.33% |
| 6 | 68 | 40 | 1 | 45.45 / 1159.26 ms = 3.92% |

The exception was the initial DCD call of frame 40 in repeat 6, with 18,075 active pairs and no newly active pair relative to the preceding DCD call. Its detection/filter core cost was 4.50 ms. Thus only **one of 246 calls with nonempty active sets** across six runs had zero new pairs. All six runs completed 40 frames, converged, and passed ground-height and vertical-slab checks. The maximal measured zero-new time fraction remains below 4% in every run, even if all such calls could be removed at zero overhead. The whole-call direction remains below the plan's 1.2x gate, but zero-new active calls are possible and must not be described as absent.

The low *fraction* of new pairs in a settled frame does not imply zero new pairs. A regional certificate might still avoid some work, but this experiment gives no estimate of its benefit. The global all-or-nothing refresh direction should stop for this scene unless new evidence changes the bound.

## Per-query TOI distribution

The earlier frame-stat field `last_ccd_toi` was 1.0 in every frame because it stores only the final TOI filter result in a frame. The new opt-in diagnostic downloads TOI buffers after the unchanged kernels and records candidate counts, minima, and cumulative counts below 0.1, 0.5, 0.9, and 1.0 by pair type. Values of 1.1 are the no-hit sentinel. Logging is separate from throughput measurements.

In the four-layer cloth case, all three repeats found a simplex TOI below 1 at frame 18: 3,072 PT and 8,286 EE evaluations per run, with minimum TOIs 0.680–0.740 across repeats. Other simplex CCD calls had no TOI below 1. This confirms that a frame's final `last_ccd_toi` can miss an earlier active CCD restriction. These are query evaluations, not unique physical contact events.

A separate one-layer cloth-to-ground case used 289 cloth vertices, a 16x16 grid, 12 frames, and initial downward velocities of 0, 1, 2, 4, and 8 m/s. Each speed was run in three fresh processes under strict mode. All 15 runs completed, converged, and passed the ground-height check. Ground vertex–plane TOI results:

| Initial speed | First frame with TOI < 1 | Minimum TOI across 12 frames | Evaluations with TOI < 1 per run |
|---:|---:|---:|---:|
| 0 m/s | none | >1 | 0 |
| 1 m/s | 6 | 0.81045 | 289 |
| 2 m/s | 4 | 0.49365 | 289 |
| 4 m/s | 2 | 0.81549 | 289 |
| 8 m/s | 1 | 0.87799 | 289 |

The minimum TOI is a fraction of the proposed step, so it need not decrease monotonically with initial speed when the first impacted frame changes. This sweep records TOI values, but it does not yet measure per-query CCD iteration counts or kernel cost. The ground check is scene-specific and does not replace a general mesh-intersection test.

## Faster four-layer impact

The same four-layer, 16x16-grid scene was also run for 20 frames with 0 or 2 m/s initial downward speed. Three timer-free fresh-process runs per speed gave median frame times over frames 6–20 of 17.60 and 21.58 ms, respectively. All six runs completed and passed strict convergence plus the scene-specific separation checks. Faster descent changes when contact begins, so this comparison does not isolate speed as a CCD-query cost parameter.

In separate synchronized stage-timer runs **without TOI histogram downloads** (three per speed), the median 20-frame stage totals were:

| Stage | 0 m/s | 2 m/s |
|---|---:|---:|
| Pipeline | 555.15 ms | 663.60 ms |
| DCD detection | 116.29 ms | 135.38 ms |
| Trajectory candidates | 72.33 ms | 90.36 ms |
| CCD TOI filter | 12.91 ms | 13.06 ms |
| Dynamic-topology effect assembly, including contact | 107.30 ms | 175.68 ms |

In the separate TOI-histogram runs, the median count of PT/EE evaluations with TOI below one rose from 3,072/8,286 to 18,431/49,716. In the stage-only runs, `Filter CCD TOI` time was roughly unchanged. This scene does not support prioritizing CCD TOI kernel optimization. Stage totals are diagnostic and nested; they must not be added or substituted for timer-free throughput. The scene spends more frames in contact at 2 m/s, so this is not a controlled per-query cost estimate.
